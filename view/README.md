# CETUS 本地可视化工作台

在 CETUS 根目录双击 `StartView.bat`。需要 Python 3.12+；脚本优先复用已有 Conda `CETUS` 环境，没有时创建项目内的 `.venv/CETUS`，自动安装依赖并打开浏览器。普通 CMD 与 Anaconda Prompt 使用同一个入口。启动错误会弹窗，详细原因保留在控制台。首次安装依赖需要联网，页面本身无需互联网、地图服务或前端构建工具。

手动启动：

```powershell
python -m pip install -r view/requirements.txt
python -m view --open
```

默认地址为 `http://127.0.0.1:5000`；端口被占用时从后续 19 个端口中选择。服务仅监听本机。关闭控制台或按 Ctrl+C 退出。

启动时自动选择当前 Python 环境中的 PROJ/GDAL 数据库，覆盖该进程继承的 PostgreSQL/PostGIS/QGIS 路径，避免 `Could not set CRS` 和 `DATABASE.LAYOUT.VERSION` 错误。不会修改系统环境变量或其他软件配置。

直接调用 Conda 环境的 Python 时，也会为 CETUS 进程配置该环境的 DLL 搜索目录，避免未激活 Conda 时 NumPy/BLAS 从其他环境加载 DLL。普通 CMD 不需要提前执行 `conda activate`。

## 操作

1. 选择或填写 SHP 路径，导入建筑。自动识别 `height` 等常见高度列；没有匹配列时弹窗输入列名。高度必须全部为有限正数、单位米；无效输入取消导入，保留原方案。要求有效 Polygon/MultiPolygon 和明确坐标系，非米制投影会转换为当地 UTM。工作副本使用统一高度列。导入后按现有形态分类识别 LCZ，套用对应 LCZ1–5 参数；识别为其他 LCZ 时明确显示并回退 LCZ5。
2. 在气象路径下填写起止日期 `MM-DD`，包含首尾两天，不跨年，按 365 天非闰年处理。导入 EPW 或现有 CETUS 支持的 CSV。更改日期后重新导入。CSV 可补充气候区和经纬度；短 CSV 的日期按其现有顺序 HOY 接口处理，例如 24 行数据对应 `01-01`。EPW 使用文件本身的位置。气象区改变时，仅更新尚未人工编辑的默认建筑参数。
3. 建筑初始为灰色默认类型，数值及每天重复的日程取同气候区六类模板的等权均值；小时参数四舍五入为整数。默认建筑实际初始化采用均值，编辑器同时保留模板平均标准差。类型按钮为当前选择集准备模板，点击 Apply 后写入参数、用途和地图颜色。模板的 24 小时日程取原全年日程按小时平均后的典型日。
4. 地图支持点击、Shift 多选、Shift 拖动/框选按钮、拖动平移和滚轮缩放。随机选择比例独立于 RAD `sample`。固定种子用于复现选择及 Apply 时的采样。阴影固定为东南方向、45° 太阳高度对应的西北投影，与计算无关。
5. Building Settings 编辑选中建筑。不同参数显示“多个值”；只应用修改的字段。数值 uncertainty 是绝对标准差，日程 uncertainty 是倍率的标准差，零表示固定值。Apply 时生成一次参数实例，N、F 与各轮使用相同实例。日程支持拖动节点或逐小时输入，全年每天重复；solar 日程保留、不展示、不编辑。SHGC 是兼容输入，9.2 实际短波透射使用 WindowTransmittance，可在同表编辑。
6. Urban Settings 中 FVC、FWC 是占总场地面积的比例，调整后重新分配剩余道路/地面预算；与建筑覆盖率之和不得超过 1。切换 LCZ1–5 立即套用参数，手动编辑后显示 LCZx，点击“应用城市设置”提交。每次以 LCZx 发起模拟，保存快照到 `outputs/view/params/`；“恢复最近 LCZx”读取最近一次设置，不覆盖标准 LCZ 文件。
7. RAD 留空自动建网，仅接受当前 `RadiationNetwork` 点网络容器并校验建筑光学签名、地表面积和时段，不读取历史建筑辐射文件。当前兼容协议名仍为 `cetus-rad-network-8`，不按字符串中的数字判断 CETUS 发布版本。`sample` 控制当前 RAD 的地面采样网格，所有建筑仍参与计算。CSV 建网采用与现有 portable sky 同类的各向同性散射/最近天空片太阳近似；经纬度来自补充设置。EPW 沿用当前 RAD 的 portable sky。
8. 点击“计算 N + F”启动独立后台进程；页面可持续读取日志，停止会结束该进程及其原生求解器，不写回未完成方案。

## N/F 计算定义

`view/simulation.py` 实现完整时段的城市—建筑交替计算，复用 9.2 的 CES3 二进制建筑引擎、RAD 网络、三类地表及空气守恒方程。原 `ENERGY.coupled.simulate_coupled` 的默认逐时联合求根接口保持原样。

- **N**：完整时段城市计算 → 完整时段建筑计算。城市阶段不接收模拟建筑的显热/接地反馈，交通热源保留；建筑长波初始温度取背景温度。建筑使用城市 Ta/Tg 作为空气/地面边界，N 的建筑输出不回传 N 的城市结果。
- **F**：用 N 建筑输出初始化；完整时段城市计算接收上一轮建筑对空气的对流、通风、HVAC 热量、接地传热及表面长波状态，再运行完整时段建筑计算，产生下一轮反馈。每轮均从相同的初始物理状态及首日周期预热条件开始，避免把整个时段的轮次误当成物理时间推进。长波边界按上一轮完整时段表面温度更新。
- **iteration**：`1`–`10` 固定运行指定数量的 F 轮次；`x` 按负荷收敛提前停止，最多 10 轮。
- **收敛指标**：全部建筑汇总、按总 GFA 归一化的逐时冷负荷，连续两次建筑计算之间的最大绝对变化，单位 W/m² GFA。默认阈值 `0.1`，界面可编辑。首轮 F 与 N 比较。达到轮数上限仍未满足阈值会明确标记为未收敛，不冒充收敛结果。
- 城市每个物理小时仍要求最大热平衡残差不大于 `0.02 W/m²`；首日周期预热最少 4 次、最多 120 次，状态温差阈值 `0.1 K`，未满足时 warning 后继续。外层轮次不会替代这些内部检查。
- 冷负荷为 `max(0, -hvac_w)` 的全建筑汇总/GFA。`TotalEnergy` 为逐时 HVAC + 照明电耗，单位 kWh/m² GFA，累计指标为逐时求和。Ta/Tg/Tb 为 °C；热通量按总场地面积归一化。图中 Qsa/Qsg 为正向储热，QHFlux 为地表到空气显热，QGFlux 为地表向深层导热。

图表包括 N/F 空气温度与 Ta.bg、N/F 冷负荷、可切换工况的热通量、F 负荷变化与城市热平衡残差。完整建筑结果自动解包为 N/F JSON，页面给出文件路径和下载链接；逐时汇总可下载 CSV。

## 保存与兼容

Save 保存标准 Neighborhood JSON，新增可选 `view_state` 包含页面版本、选择集、建筑均值/不确定性、LCZ 标签、日程编辑信息和模拟设置。普通 Python/CLI 仍可读取与运行；不要求使用 Flask。

SHP 配套文件、气象、RAD、天空矩阵及已存在的建筑二进制结果复制到 JSON 同目录，用方案名及依赖类别作前缀避免冲突。JSON 内统一使用相对路径。`Neighborhood.loadJSON` 按 JSON 所在目录解析这些路径，移动整个目录后仍可读取。

Load 没有页面元数据的 Neighborhood 时保留实际建筑、气象和城市参数，按数据恢复日期，清空选择集，不猜测模板均值/标准差。自定义城市参数标为 LCZx。SHP 缺失时可以检查和保存参数；计算前要求存在匹配的几何文件。

运行数据位于 `outputs/view/`，包含输入副本、每轮建筑档案、最终结果和日志，不纳入版本控制。
