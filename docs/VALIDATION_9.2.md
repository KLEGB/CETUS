# CETUS 9.2 接口重构与实跑验证

日期：2026-10-25。仅将建筑完整结果外置，不移除 Neighborhood 中的建筑参数、Climate 或城市结果。原生热工内核沿用 9.1，运行不校验引擎 SHA、不编译。

## 大小比较

使用 756 栋建筑、总 GFA 约 2,415,770.8 m² 的既有 SHP/龙岩 EPW 组合，HOY 5016–5087 共 72 小时。两版读取同一份输入参数，复用同一 RAD 网络，均用可见光 0.7/NIR 0.2、300 lx 控制、屋面/硬质地面 8–13 μm 选择性材料和一次漫反射。基线 9.1 显式采用相同 0.1 K 预热阈值，隔离接口重构与预热设置的影响。

大小为实际 UTF-8 JSON 文件字节数；两版均调用各自的 saveJSON、indent=2。MB 为 1,000,000 bytes，不是进程内存/RSS。

| 指标 | 9.1 | 9.2 |
|---|---:|---:|
| 计算前 Neighborhood JSON | 4.087072 MB | 3.223357 MB |
| 计算后 Neighborhood JSON | 260.915221 MB | 3.257200 MB |
| 外部建筑结果 | 原建筑逐时 JSON 163.335722 MB | CER 二进制档案 34.882250 MB |

计算后 Neighborhood 减小 **98.7516%**。9.2 由输入阶段到计算后的轻微增长来自 Climate 城市结果和结果文件引用，而不是建筑结果。建筑参数与日程保留；原历史结果字段从 Neighborhood JSON 中排除。

CER 档案包含建筑参数副本、解析后的模型、最终逐时边界、全部建筑/表面结果、照明数据与审计。它采用 ZIP 无损压缩，结果区保留原生二进制数值；不能把相对于未压缩 JSON 的全部体积差都归因于二进制编码本身。解包后的完整 JSON 另含这些副本及边界，因此可以比旧版单独建筑结果 JSON 更大。

## 测试

**53 项 Python 测试通过**。保留原物理回归测试，并按新接口调整建筑结果读取和预热行为断言。新增覆盖：

- 全部建筑结果及参数副本、实际边界和状态完整解包；
- 编辑 Neighborhood 后旧档案参数不变；
- Neighborhood 保存/加载仍保留 Climate 城市结果和可编辑建筑参数；
- 原生二进制结果及群组汇总的读取、参数单位与布局一致性；
- `python -S EnergyUnpack.py` 在没有第三方模拟依赖时完整导出；
- 不读取 SHA、不调用编译器，缺失可执行文件明确报错；
- 预热超过上限时发出 RuntimeWarning 并继续，预热不打印；最后一轮保留实际求解状态，耗尽轮数的检查点可继续使用；
- 正式求解失败时不发布完整档案，城市对象不被失败结果覆盖；
- 多波段耦合的回填后发射/反射参数进入外部档案；
- 断续重启、JSON/二进制物理一致性和原有热收支测试。

Go 物理源码和随包内核未改动，本轮没有声称重新编译或重做 ASHRAE 年验证。先前 9.1 光谱、1.9 照明及 ASHRAE 结果作为历史物理验证记录保留。

## 用时与边界

同一环境并发对照，耦合阶段（包含预热与默认写出）9.1 约 220.35 s，9.2 约 229.29 s。9.2 增加完整输入边界与参数归档，本轮主要收益是状态体积和输入/结果分离，不宣称求解加速。解包耗时不计入耦合阶段。

原生可执行文件支持 Linux x64/Windows x64；本轮在 Linux 实跑，Windows 沿用 9.1 随包可执行文件，未在 Windows 环境复测。SHP 与 EPW 地理不匹配沿用既有组合，本测试用于接口与数值一致性，不是当地真实气候预测。
